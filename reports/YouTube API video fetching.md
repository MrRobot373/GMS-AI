# Search, hydrate, and embed lesson videos

An LMS should find public lesson videos with `search.list` when it has a query, or with `playlistItems.list` when the course is already a YouTube playlist, then call `videos.list` once for the chosen IDs, and play each video only in YouTube’s iframe at `https://www.youtube.com/embed/VIDEO_ID` or the privacy-enhanced `https://www.youtube-nocookie.com/embed/VIDEO_ID`. That sequence is what the YouTube Data API v3 reference and the API Services agreement actually grant: the Data API returns identifiers and metadata, and audiovisual playback stays inside the official player. Public search and public video reads authenticate with a server-held API key. OAuth is for the signed-in teacher’s own private data and for caption download on a video that user can edit. After the **1 June 2026** change recorded in Google’s revision history, one `search.list` call costs **1 unit** in a Search Queries bucket whose default is **100 calls a day**, and one `videos.list` call costs **1 unit** from the shared **10,000-unit** daily pool, so attaching five videos is one search unit plus one hydrate unit. Metadata fetched with that key may be kept only as long as the lesson needs it and **no longer than 30 days** without a refresh or a deletion. The video file is not something the LMS is allowed to store.

## A known playlist stays on the one-unit metadata pool

When the instructor already has a playlist, start with `playlists.list` (`part=snippet,contentDetails,status,player`) and page `playlistItems.list` (`part=snippet,contentDetails,status`, `maxResults` up to **50**) until `nextPageToken` is absent. Each item’s `contentDetails.videoId` is the ID to hydrate, and lesson order is the zero-based `snippet.position`. A channel’s uploads are the playlist ID in `channels.list` `contentDetails.relatedPlaylists.uploads`. The search method page tells callers to read that playlist with `playlistItems.list` rather than `search.list` ordered by date, because date order can lag the index and a channel-scoped video search without an owner filter stops at **500** videos ([Search: list](https://developers.google.com/youtube/v3/docs/search/list)). The channel resource page names `playlists.list` as the follow-up ([Channels](https://developers.google.com/youtube/v3/docs/channels)). Those sentences describe different objects: `playlists.list` returns the playlist record, including title, privacy (`public`, `unlisted`, `private`), and `contentDetails.itemCount`, while `playlistItems.list` returns the ordered videos. Neither call returns duration or `status.embeddable`. The `playlists.list` part prose still mentions `author` and `timeCreated`; the playlist resource table, updated **15 October 2026**, defines `snippet.publishedAt`, `channelId`, `title`, `description`, `thumbnails`, `channelTitle`, `defaultLanguage`, and `localized` instead. Code against the resource table ([Playlists](https://developers.google.com/youtube/v3/docs/playlists); [Playlists: list](https://developers.google.com/youtube/v3/docs/playlists/list)).

A text query is `GET https://www.googleapis.com/youtube/v3/search` with `part=snippet`, `type=video`, and `q`. Each hit is a `youtube#searchResult` whose useful payload is an ID plus a short snippet: title, description, thumbnails, channel, `publishedAt`, and `liveBroadcastContent` (`upcoming`, `live`, `none`). The property prose says `id.type`; the property name and the code samples use `id.kind` with values `youtube#video`, `youtube#channel`, and `youtube#playlist`. Prefer `id.kind`. The parameter text says `part` must be `snippet`, while an official Apps Script sample sends `id,snippet`. The page does not say which of those is still required ([Search: list](https://developers.google.com/youtube/v3/docs/search/list); [Search](https://developers.google.com/youtube/v3/docs/search)). Duration, privacy, license, embeddable status, and caption availability are absent from the search resource. They come from `videos.list`. Filters worth setting before a lesson is attached are `videoEmbeddable=true` (the page lists `any` and `true`), `videoCaption=closedCaption`, `videoDuration` (`short` under four minutes, `medium` from four to twenty, `long` over twenty), `safeSearch` (`moderate` by default, `none`, or `strict`), `relevanceLanguage`, `regionCode` (the documented default is **US**), and `videoCategoryId`. `maxResults` accepts **0 to 50** and defaults to **5**. The API can return fewer items than requested. Pagination follows `nextPageToken`. `pageInfo.totalResults` is an approximation, caps at **1,000,000**, and must not be used to build page links. `relatedToVideoId` was removed from the documentation on **7 August 2023** ([Revision History](https://developers.google.com/youtube/v3/revision_history)).

There is no educational boolean. The curated topic list still published on the search method page has Knowledge (`/m/01k8wb`) and does not have a topic titled Education. Category titles are region-scoped: resolve them with `videoCategories.list` for the lesson’s `regionCode`, keep an ID whose `snippet.assignable` is true, and pass that ID as `videoCategoryId` or check `videos.snippet.categoryId` after hydrate. No page in these notes publishes a fixed ID for Education. `channels.list` `categoryId`, the old guide-category filter, is deprecated ([Search: list](https://developers.google.com/youtube/v3/docs/search/list); [VideoCategories](https://developers.google.com/youtube/v3/docs/videoCategories); [Channels: list](https://developers.google.com/youtube/v3/docs/channels/list)). Search’s `videoDefinition` uses `high` and `standard`. The video resource’s `contentDetails.definition` uses `hd` and `sd`. They are different enums.

Hydrate with `GET https://www.googleapis.com/youtube/v3/videos` and exactly one filter. For known IDs that filter is `id`, a comma-separated list. `maxResults` applies to `myRating`, which needs authorization, and does not apply to `id`. The method page does not state how many IDs one call accepts, and it does not say whether one unknown ID fails a mixed list or is omitted. It does document `videoNotFound` (**404**) when the video being retrieved cannot be found ([Videos: list](https://developers.google.com/youtube/v3/docs/videos/list)). The playback notes did not re-fetch that method page and leave open whether a private or unknown ID comes back as an empty `items` array or as that 404. Parse the current reference, and treat a missing item as unavailable. The lesson call is `part=snippet,contentDetails,status`. One response then carries title (maximum **100** characters), description (maximum **5000** bytes), an ISO 8601 duration that can differ by about a second from playback, thumbnails including `fhd`, `qhd`, and `uhd` on some videos, `status.embeddable`, `status.privacyStatus` (`public`, `unlisted`, `private`), `status.license` (`creativeCommon` or `youtube`), `contentDetails.caption` (the string `true` or `false`), definition, `contentDetails.regionRestriction`, `status.madeForKids`, `publishedAt`, `channelTitle`, and the language fields ([Videos](https://developers.google.com/youtube/v3/docs/videos)). Add `player` for embed HTML, `statistics` for public view and like counts, and `topicDetails` for Wikipedia topic URLs. `statistics.dislikeCount` has been owner-only since **13 December 2021**. The overview sample, on a page also stamped **15 October 2026**, still shows a `videos` array, `aspectRatio`, a public dislike count, and `PRIVACY_PUBLIC`. Those pages disagree. Use the resource property table ([YouTube Data API Overview](https://developers.google.com/youtube/v3/getting-started)).

`status.embeddable=true` is the uploader’s switch, and the same field says an embed can still be blocked by platform policy or a Content ID claim. `contentDetails.licensedContent=true` means a content partner claimed the video. Partners can set embed allow and block rules by domain and by app ID. That flag is a warning. `contentDetails.caption=true` means a track exists. It is not the transcript. If the LMS already holds a public watch URL and only needs embed HTML, title, author, and a thumbnail, `https://www.youtube.com/oembed` answers without an API key. A live call on **21 October 2026** for `jNQXAC9IVRw` returned JSON whose `html` is an iframe aimed at `https://www.youtube.com/embed/jNQXAC9IVRw?feature=oembed`, with no duration, description, privacy, license, caption flag, or category ([live oEmbed response](https://www.youtube.com/oembed?url=https%3A%2F%2Fwww.youtube.com%2Fwatch%3Fv%3DjNQXAC9IVRw&format=json)). Google’s Data API reference does not document oEmbed. The oEmbed specification’s sample is still a Flash object, and that sample disagrees with the live iframe ([oEmbed](https://oembed.com/)). oEmbed does not search, and it does not return the status fields a lesson should check before it embeds.

## Five videos cost one search unit and one hydrate

YouTube Data API v3, with methods relative to `https://www.googleapis.com/youtube/v3`, is a quota system. Every call sends an API key (`key`) or an OAuth 2.0 token (`access_token` or `Authorization: Bearer`). The pages current on **21 October 2026** do not publish a dollar price or a self-serve paid tier. A **9 November 2020** Issue Tracker reply said there was no cost and that the default was 10,000 units with no plan then to raise it. That reply is historical, it does not mention separate search and upload buckets, and it has not been reissued as a 2026 price ([Issue Tracker 172776504](https://issuetracker.google.com/issues/172776504)).

Projects that enable the API receive three default daily buckets, reset at **midnight Pacific Time**: **100** `search.list` calls, **100** `videos.insert` calls, and **10,000 units** for every other method ([YouTube Data API Overview](https://developers.google.com/youtube/v3/getting-started); [Quota and Compliance Audits](https://developers.google.com/youtube/v3/guides/quota_and_compliance_audits)). Google’s revision history for **1 June 2026** states that the API is transitioning to a granular quota system, starting with `videos.insert` and `search.list`, so YouTube can check extension requests against specific methods ([Revision History](https://developers.google.com/youtube/v3/revision_history)). The `search.list` method page states the current impact directly: **100 calls per day**, and a quota cost of **1 unit** in the Search Queries bucket ([Search: list](https://developers.google.com/youtube/v3/docs/search/list)). The **15 October 2026** overview and the quota calculator’s table say the same thing. The calculator’s auto-generated summary still says methods such as `videos.insert` have the highest cost of **1,600** points. That summary disagrees with the calculator table, the 1 June 2026 revision, and the overview, which put `videos.insert` at **1 unit** in its own 100-call bucket. The **4 December 2025** revision is the bridge on upload cost, from about 1,600 units to about 100, later superseded for bucket accounting by the June split ([Quota Calculator](https://developers.google.com/youtube/v3/determine_quota_cost)). For lesson fetch, trust the method page. Search is 1 unit in the 100-call bucket, and it no longer spends the 10,000-unit pool. Counting each search as a draw on that pool is the wrong ledger after the split. The default remains **100 searches a day**. No page in these notes quotes a pre-June unit price of 100 in those words.

`videos.list`, `playlistItems.list`, `playlists.list`, `channels.list`, and `videoCategories.list` each cost **1 unit** from the shared pool. The videos, playlist-items, playlists, and search method pages print those costs themselves. `captions.list` costs **50** units from the same pool. `captions.download` costs **200** on its method page. `videos.batchGetStats`, added **3 June 2026**, costs 1 unit in a separate 10,000-unit bucket and returns statistics only. Every request, including an invalid one, costs at least one point, and each extra page is another call at the method’s price ([Quota Calculator](https://developers.google.com/youtube/v3/determine_quota_cost)). Cost is per call. The overview prices “a read operation” and shows one `videos.list` URL with `part=snippet,contentDetails,statistics,status`. No current sentence says the cost is identical regardless of `part`, but nothing retrieved multiplies cost by parts, by `maxResults`, or by the number of IDs. Raising search `maxResults` from 5 toward 50 spends the same one search unit and spends the 100-call cap more slowly.

A lesson that attaches five public videos from a text search is one `search.list` (`type=video`, `videoEmbeddable=true`, `maxResults=5`) and one `videos.list` whose `id` parameter lists those five IDs with `part=snippet,contentDetails,status`. That is **1 Search Queries unit** and **1 shared-pool unit**. Opening the lesson later and refreshing the same five IDs is another shared-pool unit, not another search. The method page documents `id` as a comma-separated list and does not publish a maximum, so this example treats five IDs as one call. If a server cap splits them, each extra call is another 1 unit. If those five videos already sit on a playlist, skip search: one `playlistItems.list` page fits a handful under the 50-item page size, and that page plus one `videos.list` is **2 shared-pool units** and **0 search units**. One hundred search-built lessons would exhaust the default search bucket for the day. The same hundred lessons, refreshed only with `videos.list`, would spend 100 of 10,000 metadata units. Listing caption tracks for those five videos would be five `captions.list` calls, **250** units, and would still not return cue text.

| Step for five videos | Call | Bucket | Units |
| --- | --- | --- | --- |
| Attach from a query | one `search.list` page, then one `videos.list` | Search Queries, then the shared pool | 1 + 1 |
| Attach from a known playlist | one `playlistItems.list` page, then one `videos.list` | Shared pool only | 2 |
| Refresh on a later open | one `videos.list` of the stored IDs | Shared pool | 1 |

The made-for-kids guide still says the default 10,000-unit quota is enough to check made-for-kids status for up to **5,000** videos ([Made for Kids status](https://developers.google.com/youtube/data/guides/made_for_kids_status)). That figure disagrees with a `videos.list` cost of 1 unit per call against a 10,000-unit pool. The notes leave the arithmetic unresolved. Plan capacity from the method-page cost, not from the 5,000 figure.

`403 quotaExceeded` means the bucket is empty. The documented recovery is the midnight Pacific reset or an approved extension. Immediate retries spend nothing useful, because the units are already gone. `403 forbidden` and `403 insufficientPermissions` are credential, scope, or private-resource failures. `400` reasons such as `invalidPart`, `unknownPart`, and `invalidPageToken` are malformed requests, and they still cost at least one point ([YouTube Data API errors](https://developers.google.com/youtube/v3/docs/errors)). No Data API page retrieved here publishes a queries-per-second cap for `search.list`, `videos.list`, or `playlistItems.list`. The audit form asks applicants for a peak-per-minute figure. That is a question on the form, not a published default. Extra quota is a compliance audit through the Audit and Quota Extension Form, not a purchase. The form’s categories include Education and E-Learning, and an education use case is asked for player and embed screenshots. Approved extra quota is limited to the approved use case. Creating extra Cloud projects to multiply one product’s quota is prohibited. A project inactive for **90** consecutive days can lose access, credentials, or quota ([Quota and Compliance Audits](https://developers.google.com/youtube/v3/guides/quota_and_compliance_audits); [Developer Policies](https://developers.google.com/youtube/terms/developer-policies); [Audit and Quota Extension Form](https://support.google.com/youtube/contact/yt_api_form)).

Create the key in a Google Cloud project where the YouTube Data API is enabled. The key identifies the project for quota and reports. It does not identify a user. A standard key takes one application restriction: HTTP referrer, IP address, Android app, or iOS app ([Adding restrictions to API keys](https://docs.cloud.google.com/api-keys/docs/add-restrictions-api-keys)). A server-side LMS matches the IP restriction, including CIDR, because a referrer restriction expects a browser `Referer` that a backend call does not send. Keep the key on the server. Cloud’s general guidance prefers the `x-goog-api-key` header so the secret stays out of URLs and logs. YouTube’s own reference still documents the `key` query parameter. Both instructions are current, aimed at different layers ([Best practices for managing API keys](https://docs.cloud.google.com/docs/authentication/api-keys-best-practices); [API Reference](https://developers.google.com/youtube/v3/docs)). YouTube does not support service-account OAuth for this API. That flow returns `youtubeSignupRequired` ([YouTube Data API errors](https://developers.google.com/youtube/v3/docs/errors)).

Public `search.list` and public `videos.list` by ID need no user authorization. Unauthorized list calls return public data. Insert, update, and delete always require a user, as do `forMine`, `forDeveloper`, `forContentOwner`, and `myRating` ([YouTube Data API Overview](https://developers.google.com/youtube/v3/getting-started)). OAuth scope `https://www.googleapis.com/auth/youtube.readonly` is the read scope for the signed-in teacher’s own channel. Policies tell a read-only client to request that scope rather than a read-write scope, and to wait to request write access until a write feature exists ([Developer Policies](https://developers.google.com/youtube/terms/developer-policies)). `captions.list` and `captions.download` both require `https://www.googleapis.com/auth/youtube.force-ssl` or `https://www.googleapis.com/auth/youtubepartner`, and download additionally requires permission to edit the video ([Captions: list](https://developers.google.com/youtube/v3/docs/captions/list); [Captions: download](https://developers.google.com/youtube/v3/docs/captions/download)). An API key cannot download caption tracks for another channel’s public lesson.

## The official iframe carries the playback grant

After a video ID comes back from search, playlist items, or a video resource, the player URL is built by substituting that ID into `https://www.youtube.com/embed/VIDEO_ID` ([Player parameters](https://developers.google.com/youtube/player_parameters)). The IFrame Player API loads `https://www.youtube.com/iframe_api`, implements `onYouTubeIframeAPIReady`, and constructs `YT.Player`. A hand-written iframe that script will control needs `enablejsapi=1` and the `origin` parameter, which is the scheme plus the full domain. The player-parameters example loads `https://www.youtube.com/player_api` instead. Both URLs appear in current Google docs ([IFrame Player API](https://developers.google.com/youtube/iframe_api_reference)). `cueVideoById` loads the thumbnail and waits for `playVideo()` or `seekTo()`. `loadVideoById` loads and plays. The IFrame Player API says a playback counts toward the official view count only when it starts from the player’s native play button, and `onAutoplayBlocked` fires when the browser blocks autoplay or scripted playback. The video resource, describing `statistics.viewCount` as of **24 August 2026**, says a view counts when playback starts, including autoplay, for long-form video, Live, and Shorts ([Videos](https://developers.google.com/youtube/v3/docs/videos)). Those pages disagree. Lesson logic should follow player state, and a normal API client is separately forbidden to mint its own score from views and likes.

Required Minimum Functionality, last updated **15 October 2026** and described as part of the API Terms, requires a viewport of at least **200 by 200 pixels**, recommends at least **480 by 270** for 16:9, and requires a thumbnail that starts playback to be at least **120 by 70**. Overlays, frames, and other visual elements must stay off every part of the player, including the controls. Changes to the player have to be ones the API documentation describes. Automatic playback waits until the player is visible and more than half of it is on screen, and a page must not autoplay more than one YouTube player at once ([Required Minimum Functionality](https://developers.google.com/youtube/terms/required-minimum-functionality)). The embed must send an HTTP Referer. YouTube recommends `Referrer-Policy: strict-origin-when-cross-origin` and forbids `noreferrer` on `window.open`. A missing identity is player error **153**. In that case the Watch on YouTube control still works ([Embed videos & playlists](https://support.google.com/youtube/answer/171780?hl=en)). `modestbranding` is deprecated and has no effect. `rel=0` limits related videos to the same channel. It does not turn them off. `showinfo` is ignored ([Player parameters](https://developers.google.com/youtube/player_parameters)).

`onError` splits the failures a metadata check cannot finish. **2** is a bad parameter, such as a video ID that is not 11 characters. **5** means the HTML5 player cannot play the content. **100** means the video was removed or marked private. **101** means the owner does not allow embedded playback. **150** is 101 in disguise. **153** is the missing Referer ([IFrame Player API](https://developers.google.com/youtube/iframe_api_reference)). Treat 101 and 150 as one outcome: offer `https://www.youtube.com/watch?v=VIDEO_ID`. Treat 100 as unavailable, and do not send the student to a watch page that will fail the same way. Treat 153 as an integration bug. `contentDetails.regionRestriction` holds either an `allowed` list or a `blocked` list. If `allowed` is present and the viewer’s country is absent, the video is blocked there, and an empty `allowed` list means blocked in every country. Clients must not circumvent geographical restrictions, including IP restrictions ([Developer Policies](https://developers.google.com/youtube/terms/developer-policies)). The field definition supports checking the school’s country explicitly when the server and the students are in different places. No page states that the API caller’s IP is the student’s country, and no page states that a region-blocked video is omitted from `videos.list` rather than returned with `regionRestriction` set. `contentDetails.contentRating.ytRating` of `ytAgeRestricted` marks age-restricted content. These notes did not confirm which error a signed-out student sees for that rating. No official matrix maps `licensedContent=true` together with `embeddable=true` onto 101 or 150. The embeddable field mentions Content ID blocks without naming those codes. A clean `videos.list` reduces failures. It does not replace `onError`.

Privacy-enhanced mode changes the embed domain from `youtube.com` to `youtube-nocookie.com`. Views in that mode are not used to personalize the YouTube browsing experience or ads outside the site, and ads in that player are non-personalized. The API Terms and Developer Policies still apply, and network administrators have to allow `youtube-nocookie.com`. The same help page says a child-oriented site or app must self-designate with Google’s tools even when it uses that player ([Embed videos & playlists](https://support.google.com/youtube/answer/171780?hl=en)). The fetched text names the tools and does not include their URL. On each embed, `videos.list` with at least `part=id,status` supplies `status.madeForKids`. For a video designated made for kids, the client must turn off tracking and keep data collection for that player compliant with COPPA and GDPR ([Developer Policies](https://developers.google.com/youtube/terms/developer-policies); [Made for Kids status](https://developers.google.com/youtube/data/guides/made_for_kids_status)). `status.selfDeclaredMadeForKids` is returned only when the channel owner authorized the request. Nocookie is a separate control from that check. A child-directed API client must notify Google, must not use personalized ads or remarketing, and must not perform YouTube write actions such as upload, comment, or playlist create. The policies do not define a K-12 deployment as automatically child-directed. School Restricted Mode is a network setting, Strict or Moderate, via DNS CNAME to `restrict.youtube.com` or `restrictmoderate.youtube.com`, or via the header `YouTube-Restrict`. The host list includes `www.youtube-nocookie.com`. Header filtering is not supported for native mobile apps ([Control YouTube content available to users](https://support.google.com/a/answer/6214622?hl=en)). Restricted Mode is not an iframe parameter. Whether `safeSearch=strict` matches Strict Restricted Mode was not verified in these notes.

Clients must not charge users to watch content inside an embedded YouTube player, and must not gate a video behind any action other than the play button, except a login or age verification that is ordinary for the client and is not specific to YouTube API Services ([Developer Policies §III.F.3](https://developers.google.com/youtube/terms/developer-policies)). A school login in front of the LMS fits that exception. The policies contain no example that settles a tuition- or subscription-gated course whose only video path is the embed. Selling the LMS application itself is a permitted commercial use, subject to the advertising and redistribution limits ([Developer Policies §III.G.2.a](https://developers.google.com/youtube/terms/developer-policies)). Counsel should read the charging sentence before a paid tier depends on the embed. API Terms §16.3 grants no right to reproduce or distribute audiovisual content except through the YouTube API Services in accordance with the agreement ([API Terms](https://developers.google.com/youtube/terms/api-services-terms-of-service)). If the incorporated documents conflict on API use, the API Terms take precedence. The player rules that sit beside that grant forbid modifying or blocking the player, forbid a background player, forbid separating audio from video, and forbid reaching audiovisual content by any technology other than the YouTube API Services. The consumer terms, dated **15 December 2023**, separately allow showing YouTube videos through the embeddable player ([YouTube Terms](https://www.youtube.com/t/terms)).

## Key-fetched titles expire within thirty days

What a key-based client stores is Non-Authorized Data: API data reachable without user credentials. For a lesson row that means the video ID, title, channel title, thumbnail URL, duration, embeddable flag, region restriction, and made-for-kids flag. No sentence in the retrieved terms exempts a bare video ID from API Data. Developer Policies §III.E.4.d, on a page last updated **15 October 2026**, allows temporary storage of limited amounts of that data for as long as the client needs it and for **no more than 30 calendar days**, after which the client deletes it or refreshes it. The UI that shows the data is supposed to show the current data. Statistics fetched without the uploader’s authorization follow the same 30-day cap. The longer allowance in §III.L, starting **1 June 2026**, applies only to audited developers with analytics use cases who explicitly applied, and even then titles, creator names, and comment text stay on the 30-day rule ([Developer Policies](https://developers.google.com/youtube/terms/developer-policies); [revision history of the terms](https://developers.google.com/youtube/terms/revision-history)). §III.E.4.h forbids replacing API data with independently calculated figures and forbids derived metrics. The worked example in the policy is a like count substituted for YouTube’s, or a score computed from likes and views. Building a local quality score from `statistics` is that prohibition. Storing the API title beside lesson text the LMS itself wrote is not the example the policy gives. On suspension or termination, API Terms §24.3 requires the client to stop using YouTube property and to delete all API Data from its servers.

Developer Policies §III.E.1 forbids downloading, importing, backing up, caching, or storing copies of YouTube audiovisual content without prior written approval, and it forbids making that content available for offline playback. §III.E.6 forbids scraping YouTube applications or obtaining scraped YouTube data. §III.I.14 forbids using any technology other than the YouTube API Services to retrieve API data or any portion of audiovisual content. The consumer terms forbid download except as the Service authorizes or with prior written permission, and they forbid automated access by robots or scrapers outside the `robots.txt` exception for public search engines ([YouTube Terms](https://www.youtube.com/t/terms)). Those clauses are the boundary. These notes do not describe scrape, download, or stream-extraction methods. Thumbnail bytes copied onto the LMS origin are still API data, because the Terms list photos and graphics among API data content. Hotlink `snippet.thumbnails.*.url`, or let the player draw the image, and refresh or drop that URL with the rest of the row. oEmbed’s title and thumbnail, if kept beside Data API fields, should follow the same 30-day cycle. No retrieved Google sentence says whether oEmbed JSON is “API Data” under that clause or only “Content” under the consumer terms. The stricter cycle covers both readings.

Any page that displays YouTube content, including search results, videos, channels, playlists, thumbnails, and players, must make clear that YouTube is the source, using YouTube brand features. Mixed catalogs need attribution on the YouTube items. Clients must not obscure attribution the player already shows ([Developer Policies §III.F.2](https://developers.google.com/youtube/terms/developer-policies)). If the LMS would still be useful without YouTube, the mark beside the video block is the YouTube logo, not the “developed with YouTube” logo. The logo has to be clickable and has to link to YouTube content or to the YouTube part of the application, and it must not be the most prominent element on the page. The product name must not use YouTube, YT, or You-Tube. The branding guidelines’ forbidden examples include “YouTube Education” ([Branding Guidelines](https://developers.google.com/youtube/terms/branding-guidelines)). A picker that presents `search.list` hits must not modify the returned text or images and must not merge other sources into a list presented as YouTube results ([Developer Policies §III.C.5](https://developers.google.com/youtube/terms/developer-policies)). The client must link to `https://www.youtube.com/t/terms` and must say in its own terms that users of the client are bound by the YouTube Terms of Service. Its privacy policy must say that the client uses YouTube API Services, must link to `http://www.google.com/policies/privacy`, and must explain what API data is stored. If the client uses authorized data, the policy also links to `https://security.google.com/settings/security/permissions` ([Developer Policies §III.A](https://developers.google.com/youtube/terms/developer-policies)).

For someone else’s video, caption text does not come back on an API key. `captions.list` returns track metadata and, in the method’s own words, does not contain the actual captions. `captions.download` returns the track as a file only when the caller can edit that video. The supported accessibility path for a third-party lesson is the player: `cc_load_policy=1` shows captions by default, and `cc_lang_pref` sets the caption language. The IFrame reference’s captions module documents font size and reload. It does not document an option that returns cue text to the page ([Player parameters](https://developers.google.com/youtube/player_parameters); [IFrame Player API](https://developers.google.com/youtube/iframe_api_reference)). Developer Policies §III.D.7 forbids undocumented APIs. A caption file downloaded by the school’s own channel, with OAuth, is still API data under the storage rules. No page retrieved here says that file may be shown as a transcript beside the embed.

The loop that satisfies both the quota split and the storage rule is short. Search or walk the playlist only to choose. Persist the ID and the fields the lesson UI shows. On lesson open, and at least every 30 days, call `videos.list` with `part=snippet,contentDetails,status`. If the item is missing, show an unavailable state and delete the cached metadata. If `embeddable` is false or `regionRestriction` excludes the deployment country, do not iframe it. If the iframe then returns 101 or 150, replace the player with the watch-page link. If it returns 100, show unavailable and do not link out. Unlisted is a documented privacy status. These notes did not confirm that `search.list` returns unlisted videos. A stored unlisted ID can still be loaded by ID while the uploader leaves it unlisted and embeddable. A later switch to private is the same outcome as error 100. Search responses are API data under the same 30-day rule, and §III.C.5 forbids rewriting them when they are shown as search results, so the search payload is a poor permanent catalog.

## Conclusion

The quota change and the storage rule point at the same design. Search is a discovery budget of 100 calls a day. Revalidation of videos the LMS has already chosen belongs on `videos.list`, where a handful of IDs is one unit and a day’s refreshes fit inside the 10,000-unit pool. An integration that re-runs search on every lesson open spends the scarce bucket to recover an ID it already holds, and it fights the 30-day refresh rule at the same time.

A successful hydrate is also a different event from a playing iframe. Content ID, a partner domain rule, a region list, and a missing Referer all fail after `videos.list` looked clean, and the IFrame docs and the video resource currently disagree about what even counts as a view. The work is finished when `onError` separates 100, 101/150, and 153, and when `status.madeForKids` turns the LMS’s own trackers off per video. An education quota audit asks for screenshots of that same player. The agreement and the extension form are judging one implementation.
