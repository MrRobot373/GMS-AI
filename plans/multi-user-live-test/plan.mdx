## What this test proves

Five people use GEM AI at the same time, on purpose, for long enough that tools, memory, approvals, and permissions have to hold. The pass is not a green unit suite. It is a recorded Pass, Fail, or Blocked for every scenario below, with the model chip, the tool names that actually ran, and the files or citations that came back.

Done means all of the following:

- Every sidebar section a person is allowed to see was used in a session longer than a single prompt: Chat, Documents, Projects, Knowledge, Calculators, Learning, Work AI, and, where the install allows it, Super AI and Agent AI. Computer AI stays off for the whole campaign, and its row is recorded as Blocked.
- The same jobs were given to Work AI, Super AI, and Agent AI, one after another, and the timelines were compared.
- Every chat tool and every task tool in the inventory was either seen in a timeline or marked Blocked with the reason.
- A second person could not read the first person's private chat, private document, private project, or task folder, including while both were waiting on the model.
- SearXNG was the only web search, and cited numbers matched the pages that were opened.

This plan does not change product code. After it is approved, the work is to create the users, run the waves, and write `plans/multi-user-live-test/results.md`.

</RichText>

<Callout id="callout-gpu" tone="decision">

## How a row is scored

Each case is Pass, Fail, or Blocked. Blocked is for a missing install (no Claude Code SDK, no opencode, no vision for read_image, Code section off) or for Computer AI, which stays off on purpose. A wrong number, a missing tool the prompt required, a cross-user leak, or a hang with no error is Fail. Turning Computer AI on is a Fail.

Record the person, the workspace shown in the sidebar, the model chip and the reason Auto gives, every tool name in the timeline in order, and the file or citation checked by hand. Screenshots go next to the row only when the failure is visual.
